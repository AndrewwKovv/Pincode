# Деплой бэкенда на Amvera Cloud

Amvera — российский облачный хостинг (соответствует требованию 152-ФЗ о
хранении персональных данных на серверах в РФ, см. CLAUDE.md). Ниже —
пошаговая инструкция для этого проекта.

В репозитории уже подготовлено:
- `Dockerfile` — собирает образ, накатывает миграции Alembic и запускает Uvicorn.
- `amvera.yaml` — манифест Amvera (Docker-режим).
- `.dockerignore`.

## 1. Регистрация и CLI

1. Зарегистрируйтесь на [amvera.ru](https://amvera.ru).
2. Установите CLI (опционально, но удобно):
   ```bash
   curl -sSL https://raw.githubusercontent.com/amvera-cloud/cli/master/amvera-install.sh | bash -s -- v1.2.2
   amvera -v
   ```

## 2. Поднять управляемый PostgreSQL

1. В консоли Amvera: **PostgreSQL → Создать базу данных**.
2. Тариф — не ниже **Starter** (на нём гарантирована стабильная работа).
3. Задайте имя БД, логин и пароль — это будут ваши прод-креды (не путать с
   локальными `pincode_app`/`pincode_dev_password`, которые существуют только
   на вашем Mac).
4. Дождитесь статуса «PostgreSQL running».
5. Запишите **внутреннее доменное имя для чтения/записи**, оно выглядит так:
   `amvera-<ваш_логин>-cnpg-<имя_проекта>-rw`.

## 3. Создать проект бэкенда и подключить репозиторий

```bash
git remote add amvera https://git.amvera.ru/<ваш-логин>/<имя-проекта>
```

Дальше деплой — это просто:
```bash
git push amvera master
```
(логин/пароль — от аккаунта Amvera).

Важно: пушить нужно из папки `backend/` как отдельный git-репозиторий, либо
настроить деплой конкретной подпапки монорепозитория в интерфейсе Amvera
(там есть опция указать корень проекта). Если ещё не инициализировали git —
```bash
cd backend
git init
git add .
git commit -m "Initial backend"
git remote add amvera https://git.amvera.ru/<ваш-логин>/<имя-проекта>
git push amvera master
```

## 4. Переменные окружения

В интерфейсе проекта → **Переменные** → добавить:

| Имя | Значение | Как секрет? |
|---|---|---|
| `DATABASE_URL` | `postgresql+psycopg2://<логин>:<пароль>@<rw-домен-из-шага-2>:5432/<имя_бд>?sslmode=require` | да |
| `JWT_SECRET` | случайная длинная строка, **не** `dev-secret-do-not-use-in-production` | да |
| `JWT_ALGORITHM` | `HS256` | нет |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `60` (или больше для мобильного) | нет |
| `CORS_ORIGINS` | адрес вашего веб-вьюера, например `https://pincode-web.amvera.io` (или `*` пока веб не задеплоен) | нет |

Сгенерировать `JWT_SECRET`:
```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

После добавления переменных — перезапустите контейнер (переменные не
подхватываются на лету, только при рестарте, это особенность Amvera).

## 5. Хранилище файлов (PDF, фото)

`Dockerfile` уже прописывает `STORAGE_ROOT=/data/storage`, а `amvera.yaml`
монтирует постоянный том в `/data` (`persistenceMount: /data`). Это значит,
что загруженные файлы переживут передеплой — но **не размазаны по нескольким
инстансам**: если позже понадобится масштабирование на несколько реплик,
нужно будет перейти на настоящее S3-совместимое хранилище (Yandex Object
Storage / Selectel — так и планировалось в CLAUDE.md для Фазы 2). Для одного
инстанса и MVP текущей схемы достаточно.

## 6. Первый деплой и проверка

```bash
git push amvera master
```

После деплоя проверьте:
```bash
curl https://<ваш-проект>-<ваш-логин>.amvera.io/health
# {"status":"ok"}
```

Важно проверить, что RLS действительно работает на проде (миграция
`row_level_security_policies` применяется автоматически через `alembic
upgrade head` в `CMD` контейнера, но роль подключения должна быть НЕ
суперпользователем — уточните у поддержки Amvera/в консоли, что выданный
вам пользователь БД не имеет `BYPASSRLS`). Быстрая проверка изнутри
контейнера (или временно через `psql` с теми же кредами):
```sql
BEGIN;
SET LOCAL app.current_company_id = '00000000-0000-0000-0000-000000000000';
SELECT count(*) FROM projects; -- должно быть 0, даже если в базе есть данные
ROLLBACK;
```

## 7. Домен

Бесплатный HTTPS-домен вида `https://<проект>-<логин>.amvera.io/` создаётся
в разделе **Домены** — по умолчанию не активен, нужно один раз включить.

## 8. Обновление мобильного приложения и веба под прод

Сейчас `API_URL` захардкожен на `http://localhost:8000`
(`src/api/client.ts` в мобильном приложении и `NEXT_PUBLIC_API_URL` в
`web/.env.local`). После деплоя нужно заменить оба на прод-адрес
Amvera — иначе телефон и веб продолжат стучаться на локальный Mac.
